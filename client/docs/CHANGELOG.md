# Changelog

Builds 37 to 89 had one notes file each; they are condensed here. The full notes are in the Build 89 release archive.

- 37-42: Correctness fixes across recording, transcription and replies; long recordings; automatic deletion.
- 43-50: Live transcription while recording; network drops are retried; it starts where the recording did and can transcribe what came before; the pass after recording reuses it; one-file backup.
- 48-55: Speaker labelling split between server and browser; spoken speaker names.
- 56-61: Spoken commands shown in the transcript; language count; live translation panels, translated in batches.
- 62-69: A spoken menu addressed by number; a translation model separate from the reply model; scrolling and GPU fixes.
- 70-80: Translation queue and language detection fixes; a shorter voice grammar; a second reading of the recording; consistent buttons.
- 81-82: Speakers named from the conversation; the naming policy becomes a setting.
- 83: Four hours of continuous operation is a stated limit.
- 84: The recording shows how long it can continue and what will stop it.
- 85: Project structure and privacy cleanup.
- 86: Stricter language detection; suspicious repeats are checked against the audio.
- 87: Audio-backed review of transcript echoes.
- 88: Spoken instructions must be addressed as "system", a letter and a number; the strict release gate runs again.
- 89: Live transcripts keep their beginning and are saved every minute; one spoken-command system; integrity-only static tests; no code comments.
- 90: Unused code, CSS and text removed; shorter help and settings hints; WebM Clusters get known sizes; the echo review listens with a margin.
- 91: End-to-end test for spoken instructions; the cleanup pass and automatic pipeline no longer cancel each other; Delete all text keeps unsaved recordings; a conversion cannot restore deleted audio; a spoken restart waits for the save.
- 92: A spoken name ends at "stop"; the Build 91 fixes get tested functions with mutation guards; a live window counts as transcribed once its text is placed; a spoken rename can shorten a name; a translation that arrives after its line was corrected is dropped; record IDs start at a random offset per tab; 53 declarations are no longer exported.
- 93: The default reply model becomes qwen3.8:27b; a model already saved in the browser still wins over the default.
- 94: The overlap reviewer stops calling repeats suspicious; the recording line reports space and battery instead of two storage deadlines and is cleared when recording stops; page controls appear at the top of every page after the first; the spoken-commands section leaves the help overlay.
- 95: A reply waits out a model load under supervision instead of charging it against the 45-second first-byte timeout; a swap the server does not make on its own is helped along once; replies keep the model resident for half an hour; changing the model drops the cached choices.
- 96: The version under the help button is the build the page is running, and is a button: tapping it checks for a newer build and, once one is really serving, reloads into it; a build still downloading is never offered, and nothing reloads during a recording.
- 97: The battery figure appears only once the battery has measurably drained a few percent; a device on mains, or a browser that will not disclose the battery, says nothing about one instead of claiming to be on power.
- 98: The document carries its own build stamp, kept in step with BUILD_NUMBER by the release tool, so the version badge reports the build of the page rather than inferring it from whichever worker answers.
- 99: Each build carries its own file timestamps, so a conditional request can no longer answer 304 across two builds and strand a browser; the update check also re-fetches the worker script past the HTTP cache and can clear a shell the browser refuses to replace.
- 100: The text captured live is text: it is shown after a crash recovery, backed up, deleted by delete-all-text and expires on the text clock; audio dropped because the server fell behind is transcribed after recording instead of being counted as heard; a window that cannot be prepared no longer strands the live transcript; a backup that failed stops the deletion it was offered for; the default reply model becomes gemma4:31b.
- 101: Tapping the waveform can no longer trap the page where the browser has no fullscreen API; a saved transcript is shown word for word instead of being run through the live overlap trimmer; a job that is still running keeps its busy button and progress bar across a repaint; emptying the AI instructions box really does restore the default.
- 102: A recording that stops hearing anything says so within four seconds, keeps running, and is marked incomplete; a track that mutes counts as that; a file never claims more audio than arrived; the backfilled prefix is bounded; a reply server that will not answer is given up on.
- 103: The live transcript moves to a store of its own, so the three-second heartbeat no longer rewrites it twenty times a minute; a transcript written by an older build is still read where that build left it.
- 104: A recording outranks a schema upgrade: a tab that is recording keeps its database and the upgrading tab is told it is waiting; a tab that does step aside reopens instead of throwing for the rest of its life; a tab left behind by a newer build says so plainly.
- 105: A failed database upgrade no longer commits a half-built schema under the new version number; pausing live transcription keeps the transcript and coverage map instead of blanking the panel and re-transcribing the recording; a screen lock granted after it was switched off is released; a live view closed before it reports ready stops being tracked; an attribute is escaped for attribute position. First unit suite for the live transcriber, and build notes stop being deleted.
- 106: The numeric spoken-command system is removed. A speaker name worked out from the conversation is now suggested rather than applied, and nothing changes until somebody says "confirm speaker N" out loud; a suggestion needs a full point of self-given evidence, must be clear of any rival name, and expires if nobody answers it.
- 107: A compressed recording is no longer accused of capturing no audio; the watchdog now watches whatever is actually feeding the recording and judges it on that source's cadence. The overlap reviewer reports which passage it is on and is bounded in seconds rather than minutes. The recordings list is painted before startup maintenance and never fails silently. The maximised waveform turns with the phone; the ordinary interface does not.
- 108: Finalized audio moves out of recording rows so listing and storage totals never materialize whole recordings; Opus becomes the default; unreliable battery estimation and the redundant third repetition review are removed.
- 109: Schema version 11 rebuilt the database instead of migrating it; one AI model serves replies and translation; the retention sweep keeps its decision about live transcripts.
- 110: The tail of an interrupted recording stays reachable instead of being discarded; a live window can no longer answer into the session that replaced it, even at the same recording id; a seam survives one misheard word without repeating the phrase; a screen lock can no longer be orphaned by two overlapping requests. A section the server refused is retried, a quiet section says no speech was detected rather than claiming the transcript is unavailable, a run of either is reported once over the span it covers, and neither carries a warning icon. 📋 beside Start Recording begins a recording that remembers the clipboard.
- 111: Updates never delete stored notes, and a version waiting on a recording starts as soon as it stops; audio is written only together with the recording that owns it, so deleting during a conversion stays deleted; the storage counter counts each recording once; Continue cannot leak context into a later recording; the background retention sweep no longer interrupts an idle tab; a tab left on an older build says so instead of going blank.
- 112: A tab hands the database to a newer version only when nothing it started is still writing, so automatic transcription after a recording, and any running transcription, reply or conversion, keeps its result; the waiting notice says which kind of work it is waiting for.
- 113: Tapping a context item's text opens it in full and 📋 beside it copies the whole text, replacing the view button; a recording that fails to start drops its context; silence notes stay out of the text sent to the AI; free space under a gigabyte shows in megabytes; startup recovery and jumping to a note use an index instead of reading every recording (schema 12, additive); the buttons beside Start Recording are repainted on change instead of polled; a capture or space warning no longer suggests confirming a speaker; the update-check browser test waits for the worker instead of a fixed time.
- 114: 📝 is always beside Start Recording and, when idle, starts a recording with live transcription on, mirroring 📋 on the other side; a plain start follows the live-transcription setting instead of inheriting the previous recording.
- 115: 📋 beside Start Recording is drawn a fifth larger so it matches 📝 on the other side.
- 116: 📋 stays beside Start Recording during a recording and adds the clipboard to that recording as another context item for the AI reply; the live row shows how many items it carries.
- 117: The big button says Stop Recording without a timer, the live row is titled by date and time alone with the running time beside it, and the three record buttons stay on one line on a phone.
- 118: When the clipboard cannot be read or is empty, 📋 opens a multi-line box of its own instead of the browser prompt; a pasted context item can be 100,000 characters, and a single item too big for the AI reply is shortened to fit instead of dropped.
- 119: Replies, translation and the preload ask for one context size, so live translation no longer reloads the model a reply left resident; the model is loaded as live translation starts; translation speed is measured from the server's generation time over three requests; translation notices leave the transcript for the box headings.
- 120: Turning on 📝 during an Opus recording no longer shortens the saved recording; hiding and showing live transcription keeps each line's own translation and speaker; completing the translations after a recording stops after three unanswered requests and can be cancelled; the live header keeps 📋 and ✕ on screen on a phone; 📋 copies the whole transcript without notices; a translation that runs out of time is retried smaller instead of resent forever; the reply's token estimate counts by kind of character, so recordings up to about 50 minutes keep the shared context and tables are no longer undercounted.
- 121: The waveform is drawn at 30 frames a second, the frame counter shows only in debug mode, and with the live panel open the waveform is a thin strip; previews are not requested when translation boxes are shown, the app is in the background, nobody spoke, or a window is about to settle the same words; the live transcript keeps its rows instead of rebuilding them; the three-second heartbeat writes a small beat in its own store instead of the whole recording (schema 13, additive).
- 122: The recording waveform's frame rate is a setting (off, 10, 15, 30 or 60 a second) that applies at once, also during a recording, and the page sleeps between frames; the release gate takes about half as long: suites run side by side where they can, the mutation guards run in parallel after the whole table is checked, and two slow spots inside suites are gone; the gate reports each suite's time; every test file and guard is checked against the contracts; the browser suites find Chromium by themselves; a release is published whole or not at all.
- 123: Auto for the recording waveform draws on every refresh of the screen the app is on, and Settings shows the refresh rate it measured; stopping a recording while the waveform is fullscreen leaves fullscreen instead of leaving the page locked with ⚙️ hidden.
- 124: Nothing is lost by surprise: Stop waits for the last seconds of the live transcript; only the overlap between two live windows is checked for repeated words, and split sentences keep their order; a failed replay keeps the live lines; recovered Opus recordings get their duration, seek index and last Cluster, and every Opus recording is as long as its file; Stop finishes on a full disk and recovery marks the result incomplete; a failed save can be downloaded and is in the backup; backup-first deletes nothing until the file is saved; Settings writes back only what was edited in the tab; a transcript outlives its fresh replies; deleting one reply leaves other work running; updates wait for any work in the tab.
- 125: Nothing stays stuck or shows the wrong state: a live window the server keeps failing on is skipped after two strikes instead of freezing the live transcript; translation boxes reach every waiting line, an outage marks no line "not translated" and they try again within 15 seconds; a silent or mislabelled window no longer opens a translation box; backfilled lines carry their language; cancelling the automatic transcription or reply stops the cleanup pass too, and a cancel is never lost while a job starts; the translation fill waits while a reply runs and retries unanswered batches, with its own notice; a tab's own save says Saving and the record button stays busy; an open tab recovers a recording whose tab closed, with Recover now and Delete meanwhile; list repaints keep playback, a title being typed and the job buttons; Enter opens a preview once and Tab stays inside dialogs.
- 126: Long recordings stay fast: the live transcript is saved as it grows instead of whole every minute (about a fifth of the writes over four hours); startup reads live transcript keys only; the offline queue's cap is the memory it really holds; speaker clustering is eight to ten times cheaper per line and runs once per window; the transcription after recording adapts how many chunks it sends at once, so a one-at-a-time server no longer times most of them out; the log viewer opens on three hours of chunks in a fraction of a second and the reply viewer writes once per frame; showing 📝 again keeps the rows on screen; a long-context reply waits longer for its first word.
- 127: No code comments in the app, its tests or its tools: what they said is carried by clearer names and by docs/ARCHITECTURE.md, and the static suite scans every file for them; each user journey is named, so a failure says which one; the transcription log viewer no longer loses a chunk that arrives again with a later start.
- 128: What is saved is what was said: a saved transcript no longer loses words to the repeat check, nor moves words spoken after a quiet minute into that minute; live transcription no longer splices old audio onto new after an outage, shows a sentence twice where two backfill windows meet, or marks a quiet window as a gap; a one-line translation that starts with a time, a date or a number is kept; automatic deletion counts from the end of a recording; deleting a transcript takes its live transcript with it, and a deletion a closed tab left half done is finished; a Stop that meets a full disk keeps what it found. Code comments that say why are allowed again. New suites saved-transcripts and storage-paths run the real modules over an in-memory IndexedDB.
- 129: A new build waits beside the one serving until you reload into it, so an open tab never runs files of two builds, and an install that fails says so and can be tried again; the shell is installed whole or not at all and a redirected index.html no longer stops the app loading; pop-up views run no script and are posted nothing; audio is converted to 16 kHz through a proper low-pass filter, in a worker; twenty-nine checks that only read source text now run the code, and their number can only go down.
- 130: A second speaker in the same room is labelled when only one language is spoken: the 60% bar sits at the clustering's own same-speaker boundary instead of well below it; the automatic gain reads its meter as floats, so a pause is no longer turned up to 24x and the words after it are no longer squashed by the limiter.
- 131: Speaker numbers show once two voices have each said two lines, whatever the confidence, and the live header counts the same speakers with how sure it is; a stray line carries the number before it; a voice whose lines have left the window still counts.
- 132: Speaker numbers stay on screen once shown, and a voice stays a voice: every regrouping starts from the lines already its own, a line moves to another voice only when it sounds clearly more like it, and two voices become one only on strong evidence; a named voice outlives an unnamed one, and two differently named voices are never joined.
- 133: Speaker numbers count 1, 2, 3 in the order people come in: the numbers on screen are kept apart from the identities the clustering keeps, so they never skip one, a join keeps the lower number and moves the later ones up, and "confirm speaker N" confirms the suggestion announced for Speaker N.
- 134: What the live transcript misses is marked and can be filled in afterwards, a word cut at a window edge is no longer shown twice, and a busy transcription server loses no section.
- 135: The app sizes itself to the box it runs on: a myAI box publishes what its hardware can take at /capabilities, translation boxes and parallel work never ask more of it, and Settings shows the box and its warnings.
- 136: An opened reply, transcript or context item can scroll by itself: ▶ starts and pauses, a speed button opens a popup to set lines a minute, the reader's own scrolling is followed, and it stops at the end.
- 137: A recording's retention countdown moves up into the room to the right of its size bar, one row instead of two, down to a 360 px phone.
